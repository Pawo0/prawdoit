## Zasady kwalifikacji

- **Zakres wskazany przez organizatora (pole `scope`, kolumna „Zakres”):** `lista` = adres lub baza z `rules/resources.txt` (MSZ/Odyseusz, RCB, RSO, IMGW, CERT Polska, PSP, Policja, GIS, PAA, urzędy morskie, MI, MON, MSWiA, KPRM, GDDKiA, ULC, UTK, Google Fact Check…; pobierane albo `reference_only`, gdy strona jest dynamiczna lub zablokowana dla automatów); `wskazane` = źródło użyte w scenariuszach referencyjnych lub instrukcjach organizatora (Demagog, PAP, EUvsDisinfo) albo ten sam serwis/instytucja co adres z listy; `rekomendowane` = wymienione tylko wśród „rekomendowanych punktów odniesienia” w treści zadania, sekcja 7 (dane.gov.pl, ISAP, EUR-Lex, korpusy organizacji IFCN/EFCSN, Check First); `spoza listy` = dodane przez zespół (GUS, NBP, Eurostat, PKW, Przedstawicielstwo KE). Uzasadnienie każdego wpisu: pole `scope_basis`; analiza i pomiar skutków ograniczenia bazy: `research/10_organiser_sources.md`. Kontrola: `python -m prawdowid.sources scope` (z `backend/`).
- **Stan zakresu:** lista: 34 źródeł (34 wł., 3267 dok.); wskazane: 9 źródeł (9 wł., 3729 dok.); rekomendowane: 9 źródeł (9 wł., 1622 dok.); spoza listy: 5 źródeł (2 wł., 85 dok.).
- **Kategoria A (źródła pierwotne/urzędowe, tier 1):** akty prawne (ISAP/ELI, EUR-Lex), dane publiczne (GUS, NBP, dane.gov.pl), komunikaty organów właściwych (gov.pl, MSZ, RCB, CERT Polska, IMGW, PSP, Policja). Organ jest źródłem kat. A w zakresie swoich kompetencji i dla faktu, że coś ogłosił.
- **Kategoria B (fact-checking — tier 2 / bazy incydentów — tier 3):** organizacje z weryfikacją IFCN lub EFCSN albo instytucjonalne bazy (EUvsDisinfo — EEAS). Liczy się tylko po dopasowaniu twierdzenia.
- **Kategoria C (media, tier 4):** tylko kontekst; nigdy samodzielna podstawa werdyktu.
- **Wykluczenia:** źródła bez identyfikowalnego wydawcy, treści generowane przez model, strony blokujące automatyczny dostęp (Incapsula/CAPTCHA, HTTP 403) lub zabraniające go w robots.txt albo z zastrzeżeniem TDM (np. PAP FakeHunter) — te najwyżej jako `reference_only` (zaufany link, bez pobierania), źródła bez daty.
- **Aktualizacja:** harmonogram w procesie API pobiera każde włączone źródło co `schedule_hours` (kolumna „Co”), CLI: `python -m prawdowid.sources run --due` (z `backend/`); stare skrypty `ingest/run_factchecks.sh` / `ingest/run_official.sh` działają jako metoda `legacy_script`. Każdy rekord ma `published_at` i `retrieved_at`; robots.txt sprawdzamy wg RFC 9309.
- **Licencje:** przechowujemy twierdzenie, ocenę, fragment i link (cytat prawem cytatu, z atrybucją); respektujemy robots.txt i sygnały `ai-train=no`; nie trenujemy modeli na tych treściach.
